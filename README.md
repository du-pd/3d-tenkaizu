# 3d-tenkaizu — 3D展開図メーカー

3Dモデル（STL / OBJ）を読み込み、**ペーパークラフトの展開図（SVG）**と
**レーザー加工用のベクターデータ（SVG / DXF）**を出力する、ブラウザ完結型の Web アプリです。

- インストール不要・URLアクセスのみ
- データはブラウザ内でローカル処理され、**サーバーには送信されません**
- GitHub Pages でホストできる静的サイト（外部依存ゼロ・単一サイト完結）
- 大学（情報デザイン系）の授業・演習で学生に使わせる教材ツールとして設計

情報デザイン系の学生がライノセラス等で作った平面主体の立体を想定しています。

## 使い方

1. `index.html` をブラウザで開く（またはローカルサーバ経由で配信）
2. STL / OBJ を読み込む。または「サンプル形状」ボタン（立方体・正四面体・正八面体・正十二面体）で動作確認
3. 展開設定（平面マージ角度・のりしろ・実寸スケール）を調整
   - 大きめのモデルは処理中にステータスを表示し、段階的にブラウザへ制御を返します
   - 必要なら「3Dプレビューで辺をクリックして切り線に固定」で自動展開の切れ目を手動調整できます
4. 出力モードを選ぶ
   - **ペーパークラフト**: 山折り／谷折り線・のりしろ・貼り合わせ番号つき
   - **レーザー加工**: 切断線（CUT・赤）と折り筋（SCORE・青）をレイヤー／色で分離
5. 「SVGダウンロード」「DXFダウンロード」または「印刷」

> ⚠ **印刷時の重要注意**: プリンタ設定の「用紙に合わせる／ページに合わせて拡大縮小」は
> 必ず **オフ（実寸・100%）** にしてください。オンだと寸法がすべて狂います。
> SVG は **mm単位** で出力され、印刷スケールを保証します。

### ローカルで動かす

ES モジュールを使うため、`file://` ではなく HTTP 配信が必要です。

```bash
npm run serve          # http://localhost:8123/index.html
```

## レーザーカット用ベクター出力

レーザー加工機のワークフローに合わせ、線種を用途別に分離して出力します。

- **CUT レイヤー（赤 `#FF0000`）**: パーツ外形とのりしろ外形＝切断する線
- **SCORE レイヤー（青 `#0000FF`）**: 折り筋＝低出力でスジ入れする線
- **ENGRAVE（任意）**: パーツ番号などの刻印

出力形式:

- **SVG**: `id` とストローク色でレイヤー分離（CUT=赤 / SCORE=青 / ENGRAVE=緑）。
  Inkscape レイヤー属性（`inkscape:label`）も付与。多くのレーザー機のカラー
  マッピング運用にそのまま乗せられます。
- **DXF (R12 ASCII)**: レイヤー `CUT` / `SCORE`、単位 mm、Y軸上向き（CAD慣習）。
  線色は ByLayer ではなく明示指定（CUT=赤1 / SCORE=青5）で、色を解決しない
  取り込みでも CUT/SCORE を区別できます。

### どの形式を使う？

| 用途 | 推奨形式 | 備考 |
|------|----------|------|
| **Illustrator / Inkscape で編集** | **SVG** | Illustrator は SVG をネイティブに開けます（レイヤー・色・実寸そのまま）。DXF取り込みは尺度や色でつまずきやすいので SVG が確実。 |
| Rhino / CAD | DXF | 実寸 mm でそのまま。 |
| レーザー機の CAM に直接 (LightBurn 等) | DXF または SVG | 機種のカラーマッピングに合わせて選択。 |

> Illustrator でレーザー用ベクターを扱うなら、まず **SVG** を試してください。DXF が
> どうしても必要で開けない場合は、症状（何も出ない／尺度が違う／色が付かない 等）に
> 応じて調整できます。

## 処理フロー（自前実装）

展開計算は既存 JS ライブラリに頼らず自前実装しています。数学的な正しさ
（回転行列・二面角の符号）を最優先しています。

1. **STLパース** → 座標ハッシュで頂点マージ（`src/parse.js`）。学生データは頂点が
   分離している前提。バイナリ／ASCII 自動判定、破損検出はエラーを握りつぶさず通知
2. **隣接テーブル構築**（`src/mesh.js`）。穴（境界辺）／非多様体辺を検出して警告
3. **同一平面の隣接三角形をポリゴンにマージ**。平面主体モデルで面数が激減する重要工程
4. **双対グラフで全域木を構築**（`src/unfold.js`）。二面角の小さい辺を優先的に残し
   （MST）、平坦部が一枚になるようにする
5. 木をたどり、共有辺を軸に回転させて2D平面へ展開（等長変換）
6. **パーツ間の重なり判定** → 重なったら枝を切って分割
7. **のりしろ生成**（`src/layout.js`）。切断辺の片側のみ・台形・隣接部と干渉しない角度
8. **二面角の符号で山折り／谷折りを判定**し線種を変える（凸辺＝山折り）
9. A4への簡易ビンパッキング配置。収まらない場合は警告 or 自動フィット縮小
10. 単一パーツが用紙を超える場合は、複数ページへクリップした**ポスター分割**で出力。
    隣接ページは**重ね代（貼り代）ぶんオーバーラップ**させ、各ページに**トンボ（四隅）**・
    **重ね代の境界線**・**タイル位置ラベル（行・列）**を付けて貼り合わせを容易にする
11. **SVG / DXF 出力**（`src/render.js`）。パーツ番号・辺番号つき

## 検証

既知形状（立方体・正四面体・正八面体・正十二面体）で数学的な正しさを検証しています。

```bash
npm test        # 幾何パイプライン + 入出力（STL/DXF）のユニットテスト
npm run test:ui # Playwright によるブラウザ動作確認（要 Chromium）
```

検証項目（抜粋）:

- 頂点溶接数・面数がオイラー標数と整合するか
- 穴／非多様体が正しく検出されるか
- 平面マージ後の面数（立方体=6, 十二面体=12 など）
- 全域木の辺数 = 面数 − 1
- **展開の等長性**（各辺の2D長が3D長と一致＝回転が正しい）
- 凸多面体の折り線がすべて山折りになるか
- バイナリ／ASCII STL のパース、破損STLのエラー通知
- DXF の SECTION/ENDSEC 対応・レイヤー・mm単位

## 構成

```
index.html          UI（警告・操作パネル・3Dプレビュー・展開図プレビュー・印刷CSS）
src/
  vec.js            2D/3Dベクトル演算
  parse.js          STL(bin/ascii)/OBJ パース + 頂点溶接
  mesh.js           隣接テーブル・穴/非多様体検出・平面マージ・二面角/山谷判定
  unfold.js         双対グラフ・全域木(MST)・2D展開・重なり分割
  layout.js         のりしろ・番号・A4ビンパッキング
  render.js         SVG(ペーパー/レーザー) / DXF 生成
  viewer3d.js       依存なしのCanvas 3Dプレビュー
  app.js            UI配線
test/               幾何・入出力・UIのテスト
```

## 既知の制限

- 平面マージの外周抽出は「単純ループ（穴なし面）」を前提。穴あき面はマージせず個別に残します
- 重なり回避は貪欲法（重なったら枝を切って別パーツ化）。最適なパーツ数にはなりません
- 手動編集は「折り線を切り線に固定」だけに絞った最小機能です。切り線を折り線へ戻す最適化や複数候補の比較は未実装です
- 単一パーツが用紙を超える場合はポスター分割SVGで出力します。DXFはページ単位のクリップを持たないため、分割ではなく全体形状を1回だけ出力します
- 減面処理は未実装
